# 08 · 音频格式支持

> 为什么有这份文档：**用户 2026-09-25 提出"这个支持的音乐格式要记下来，
> 你之前没记下来导致还要回去翻代码"。** 这类"能力清单"不记下来，每次
> 问「支不支持 X」都得重新翻三处源码 + 一个生成的配置文件。
>
> 本文是**权威答案**。改格式支持时**先改这里**，再改代码。

---

## 1. 三条完全不同的通路

**别以为音频都走 FFmpeg —— 不是。**

| 通路 | 实现 | 管哪些后缀 |
|---|---|---|
| **FFmpeg** | `app/src/main/cpp/ffmpeg_decoder.cpp` | 除 DSD 外全部 |
| **自研 `DsdReader`** | `app/src/main/cpp/dsd_reader.cpp` | `dsf` / `dff` |
| **系统音频（AAudio）** | `SystemAudioSink` | 全部，但 **DSD 明确拒绝** |

### DSD 是单独一条路

`audio_engine.cpp` 的 `AudioEngine::open()` **开头就分流**：先 `pread` 文件头 4 字节，
按 **magic** 判断，**不看扩展名**（`DsdReader::looksLikeDsd`，`dsd_reader.cpp:58`）：

| magic | 容器 |
|---|---|
| `DSD ` | DSF |
| `FRM8` | DFF |

命中就走自研解析器。

**FFmpeg 那份构建里 DSD 是故意关掉的**（`CONFIG_DSD_*_DECODER=0`、`CONFIG_DSF_DEMUXER=0`），
而且**就算打开也没用**：FFmpeg 内部的 `dsd2pcm` 是 48 抽头 FIR 低通 + 8:1 抽取，
交出来的是**有损 PCM**，而 native DSD 要的恰恰是**裸位流**。

> 也就是说：`.dsf` 文件**改名成 `.flac` 照样能放**（走 magic），
> 反过来 `.flac` 改名成 `.dsf` 放不了。

## 2. FFmpeg 是裁剪版，不是全功能

`third_party/_ff/rebuild_with_wma.sh` 用的是 **`--disable-everything` + 白名单**
（2026-09-25 重编后的当前状态）：

```
--enable-decoder='flac,alac,ape,mp3,aac,vorbis,opus,wavpack,
                  pcm_s16le,pcm_s24le,pcm_s32le,pcm_f32le,pcm_s16be,pcm_s24be,pcm_u8,
                  wmav1,wmav2,wmalossless,wmapro'
--enable-demuxer='flac,alac,ape,mp3,aac,ogg,wav,wv,aiff,mov,matroska,asf'
--enable-parser='flac,alac,ape,mpegaudio,aac,vorbis,opus'
```

> 改动只要加 `asf` 到 demuxer、加四个 WMA 解码器 —— 参数是照抄
> `ffbuild/config.mak` 里 `FFMPEG_CONFIGURATION` 那行的，**别自己重写**。
>
> ★★ **`make` 只编到源码树，必须再跑一次 `make install`** 产物才进
> `third_party/_ff/out/arm64-v8a/lib/`。只跑 make 的话 `out/` 里还是旧的，
> 而**文件大小一模一样**，极易误判成"编完了"（实测踩到：13 秒的 make + 大小没变）。
> ★ 源码树里那份没 strip（3.2 MB），`out/` 那份 strip 过（732 KB），别拿源码树的大小对比。
> ★ 产物还要拷进 `app/src/main/jniLibs/arm64-v8a/` —— 那才是进 APK 的那份。

> ## ★★ 「FFmpeg 支持 X」≠「这个 App 支持 X」

### 权威判据

查 **`third_party/_ff/ffmpeg-7.1/config_components.h`** —— `= 1` 才是真编进去了。

```bash
grep "CONFIG_.*_DEMUXER 1"  third_party/_ff/ffmpeg-7.1/config_components.h
grep "CONFIG_.*_DECODER 1"  third_party/_ff/ffmpeg-7.1/config_components.h
```

### ⚠️ 别用「搜 .so 里的符号」判断

**`grep -a ff_flac_demuxer libavformat.so` 什么都搜不到** —— 符号表被 strip 了。
连明知启用了的 `flac` 都搜不到，所以这个方法**只会给出全错的结论**。
（2026-09-25 踩过：一度得出"所有 demuxer 都没编"的结论。）

### 2026-09-25 重编后核对的全部已编组件

```
demuxer : AAC AIFF APE ASF FLAC MATROSKA MOV MP3 OGG WAV WV
decoder : AAC ALAC APE FLAC MP3 OPUS VORBIS WAVPACK
          WMAV1 WMAV2 WMALOSSLESS WMAPRO
          PCM_F32LE PCM_S16BE PCM_S16LE PCM_S24BE PCM_S24LE PCM_S32LE PCM_U8
parser  : AAC FLAC MPEGAUDIO OPUS VORBIS
```

**加新格式 = 改 `rebuild_with_wma.sh` 里的 configure 参数 → 重跑 configure + `make` +
`make install` → 产物进 jniLibs → 重新出 APK。**

## 3. 逐后缀对照表

| 后缀 | 容器 / 解析 | 解码 | **能不能播** | `Library` 扫 | 网页 JS 收 |
|---|---|---|---|---|---|
| `flac` | FLAC ✅ | flac ✅ | ✅ | ✅ | ✅ |
| `alac` | MOV ✅ | alac ✅ | ✅ | ✅ | ✅ |
| `m4a` | MOV ✅ | alac / aac ✅ | ✅ | ✅ | ✅ |
| `mp3` | MP3 ✅ | mp3 ✅ | ✅ | ✅ | ✅ |
| `aac` | AAC ✅ | aac ✅ | ✅ | ✅ | ✅ |
| `wav` | WAV ✅ | `pcm_*` ✅ | ✅ | ✅ | ✅ |
| `aif` `aiff` | AIFF ✅ | `pcm_*` ✅ | ✅ | ✅ | ✅ |
| `ape` | APE ✅ | ape ✅ | ✅ | ✅ | ✅ |
| `wv` | WV ✅ | wavpack ✅ | ✅ | ✅ | ✅ |
| `ogg` | OGG ✅ | vorbis / opus / flac ✅ | ✅ | ✅ | ✅ |
| `opus` | OGG ✅ | opus ✅ | ✅ | ✅ | ✅ |
| **`oga`** | OGG ✅ | vorbis / opus / flac ✅ | ✅ **能播** | ❌ **漏写** | ✅ |
| **`mka`** | MATROSKA ✅ | 看里面装什么：vorbis/opus/flac/mp3/aac ✅；ac3/dts ❌ | ⚠️ **多半能播** | ❌ **漏写** | ✅ |
| **`wma`** | **ASF ✅（2026-09-25 重编）** | wmav1 / v2 / lossless / pro ✅ | ✅ **（重编后）** | ✅ | ✅ |
| `dsf` `dff` | **自研 `DsdReader`** | 裸位流 ✅ | ✅ | ✅ | ✅ |

### 三条结论

1. **`oga` / `mka` 能播，只是 `Library.AUDIO_EXT` 漏写了** —— 加上就行，不用重编 FFmpeg。
2. **`wma` 原来真放不了** —— 不是名单问题，是二进制里没有 `asf` demuxer 和 WMA 解码器。
   **2026-09-25 已重编 FFmpeg 补上**，现在能放了。
   ⚠️ 但**「编进去了」不等于「能播」** —— 真机上放一遍才算数，见下面第 5 节第 7 条。
3. **网页 JS 的 `AUDIO` 正则曾经和 `Library` 不一致**（多 `oga`/`wma`/`mka`），
   其中 **`wma` 是错的**：传上去服务端会存，但音乐库不扫它 →
   **文件在手机上，App 里看不见，全程零提示**。**已修**，见下节。

## 4. ★★ 名单已经合并成一份（2026-09-25 修）

**以前三份各写各的，这才是坑的根源。**

| 位置 | 以前 | 现在 |
|---|---|---|
| `Library.kt` `AUDIO_EXT` | `private`，14 个 | **`val`，权威，17 个** |
| `WirelessServer.kt` JS 正则 | 手工维护 17 个，和上面**不一致** | `var AUDIO=/\.(${Library.audioExtRegex()})$/i;` ← **生成** |
| `tools/hifiprobe-upload.py` `AUDIO_EXT` | 与 `Library` 一致 | 同左（**Python 读不到 Kotlin，只能手工同步**） |

重复的清单不只是要同步两次 —— 它**迟早会不一致**，
而那次不一致直接表现为"网页传进去的歌在 App 里找不到"。

★ 还留着一处手工同步：上传工具的 Python 名单。**加格式时别忘它**
（`tools/hifiprobe-upload.py` 顶部的 `AUDIO_EXT`）。

## 5. 加新格式的检查清单

1. [ ] `rebuild_with_wma.sh` 的 configure 参数加上 demuxer / decoder
2. [ ] 重跑 configure + **`make` + `make install`**，产物进 `out/`，再拷进 jniLibs
3. [ ] 查 `config_components.h` 确认 `= 1`（**别搜 .so 符号**，符号表被 strip 过）
4. [ ] `Library.kt` 的 `AUDIO_EXT` 加后缀（**唯一权威名单**，网页 JS 自动跟着变）
5. [ ] `tools/hifiprobe-upload.py` 的 `AUDIO_EXT` 手工同步
6. [ ] **更新本文**
7. [ ] 拿一个真实文件在真机上**放一遍**（"编进去了" ≠ "能播"）
